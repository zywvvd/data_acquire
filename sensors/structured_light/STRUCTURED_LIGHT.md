## 1. 结构光成像原理

### 1.1 两种架构:单目结构光 vs 主动双目

「结构光」是一个**大类**,核心思想是「主动投射已知图案 + 相机观察」求深度。按相机数量分两种,
必须分清,否则会误判设备:

| | 单目结构光 (monocular) | 双目结构光 / 主动双目 (active stereo) |
|---|---|---|
| 构成 | 1 投射器 + **1** 相机 | 1 投射器 + **2** 相机(立体对) |
| 原理 | 相机看投射图案的**形变**,用「投射器-相机」基线三角测量 | 投射器撒 IR 散斑当**人工纹理**,两相机做**立体匹配**(视差→深度) |
| 典型 | 初代 Kinect、RealSense F200 | RealSense D4xx、Apple TrueDepth、**本设备** |
| 薄弱面 | 受环境光干扰大 | 弱纹理/反光/透明面仍难匹配 |

二者不互斥。「双目结构光」就是「结构光 + 立体匹配」的组合——**投射器不直接参与测距,只负责给场景
打上人工纹理**,让左右两个 IR 相机能匹配上。本设备属于这一类(下文以实测证明)。

> 纠正一处早先的过度简化:文档曾写过「结构光≠双目」,不准确。结构光与双目是两个正交维度,
> 组合起来即主动双目结构光。

### 1.2 本设备 = 主动双目:四个光学件各司其职

机身上四个光学元件(外观都像镜头):

| 元件 | 作用 | 在 SDK 里 |
|---|---|---|
| IR 散斑投射器 | 往场景投一堆红外随机点,当人工纹理 | `TY_COMPONENT_LASER`(只控制,不出图) |
| 左 IR 相机 | 拍红外图(立体对之一) | `TY_COMPONENT_IR_CAM_LEFT` |
| 右 IR 相机 | 拍红外图(立体对之二) | `TY_COMPONENT_IR_CAM_RIGHT` |
| RGB 彩色相机 | 拍可见光,**仅上色,不参与测距** | `TY_COMPONENT_RGB_CAM` |

关键:**深度不是某一个相机"看图案变形"算的,而是左右两个 IR 相机对同一片散斑做立体匹配算的。**
RGB 与测距完全无关,只负责把颜色贴到深度点上。

### 1.3 从散斑到深度:SGBM 立体匹配流水线

```
投射器撒 IR 散斑 ──► 左 IR 相机 ──┐
                                   ├──► SGBM 立体匹配(逐像素找左右图对应点)──► 视差图 d ──► 深度 Z=fB/d ──► 深度图
投射器撒 IR 散斑 ──► 右 IR 相机 ──┘
                                                                                                    │
                                              RGB 相机 ──► TYMapRGBImageToDepthCoordinate ──► 上色点云 ◄┘
```

- **SGBM**(Semi-Global Block Matching):经典立体匹配算法。对深度图每个像素,在右图同一行(epipolar
  约束)的一定范围内搜索最相似的块,水平位移即**视差 d**(像素)。左右 IR 图越像、纹理越丰富,匹配越准。
- **散斑的作用**:办公室墙面这种"没纹理"的区域,普通双目匹配会失败(一片白,找不到对应点)。
  投射器撒的随机散斑就是**人工纹理**,让每个区域都有可匹配的特征。所以投射器是深度命脉——
  关掉它深度有效率从 33% 跌到 2%(§8.2 实测)。
- 深度图 = 视差图经 `Z=fB/d` 换算后的距离图(§3)。

运行 SDK 自带工具 `DumpAllFeatures -ip 192.168.1.114`,实见 5 个组件:

| 组件 (ID) | 角色 | 关键参数(实测) |
|---|---|---|
| `TY_COMPONENT_LASER` (0x400000) | IR 散斑投射器 | power=100, auto_ctrl=1,可读写 |
| `TY_COMPONENT_IR_CAM_LEFT` (0x40000) | 左 IR 相机 | 1280×960 mono8, fx=1102.09, exposure≤990, gain∈[0,255] |
| `TY_COMPONENT_IR_CAM_RIGHT` (0x80000) | 右 IR 相机 | 1280×960 mono8, fx=1104.60,基线 B=99.89mm |
| `TY_COMPONENT_DEPTH_CAM` (0x10000) | SGBM 深度输出 | 模式: 320×240 / 640×480 / **1280×960** |
| `TY_COMPONENT_RGB_CAM` (0x100000) | RGB 纹理 | 2560×1920, 仅上色 |

**判定主动双目的铁证:**
- 存在 `TY_COMPONENT_IR_CAM_LEFT` 与 `TY_COMPONENT_IR_CAM_RIGHT` **两个 IR 相机**,且右相机有
  `TY_STRUCT_EXTRINSIC_TO_DEPTH = "rightIR to leftIR extrinsic"`,平移分量 tx = **-99.89mm**(即基线)。
- 深度组件下挂一整套 `TY_INT_SGBM_*` 参数(`DISPARITY_NUM`、`UNIQUE_FACTOR`、`LRC`、`MEDFILTER`…)。
  **SGBM = 立体匹配算法**,深度是"左右 IR 匹配出视差"算出来的,不是单相机看图案变形。

**接口代际 = Gige_2_0**:`TY_COMPONENT_LASER` 下的 `TY_INT_LASER_POWER` / `TY_BOOL_LASER_AUTO_CTRL`
均 readable+writable(access=3),走旧 `TYSetInt/TYSetBool` API(非 Gige_2_1 的 GenICam
`LightControllerSelector`/`TYParamGetAccess`)。故 SDK 对 LASER/IR 的设置全部有效,不存在"接口代际
不匹配致 no-op"(§8.1 详)。

RGB 相机与深度解算无关,只负责给点云上色(`TYMapRGBImageToDepthCoordinate`)。

## 3. 深度的几何计算

### 3.1 基本公式

双目深度由三角关系得出:

```
        f · B
   Z = ───────
          d
```

- `f`:IR 相机焦距(像素)——左 IR fx = **1102.09 px**(1280 分辨率下)
- `B`:左右 IR 基线 = **99.89 mm**(取自右→左外参 tx)
- `d`:视差(像素),即同一物点在左右图中的水平位置差
- `Z`:物距(深度,轴向)

视差越大 → 物体越近;视差越小 → 越远。`f·B = 1102.09 × 99.89 ≈ 110 080 mm²`。

### 3.2 视差搜索范围 → 工作量程(近/远端极限的计算)

SGBM 只在**有限视差窗**内搜索匹配(实测 `DISPARITY_OFFSET=25`、`DISPARITY_NUM=162`,
故 `d ∈ [25, 187]`)。视差超出这个窗 → 匹配失败 → 深度无效。代入 Z=fB/d:

```
   最近 Z_min = f·B / d_max = 110080 / 187 ≈ 589 mm  ≈ 0.59 m
   最远 Z_max = f·B / d_min = 110080 / 25  ≈ 4403 mm ≈ 4.41 m
```

→ **工作量程 ≈ 0.59–4.4 m**。这就是近/远端极限的来源:**视差搜索窗的上下界**,经 Z=fB/d 换算成距离。
实测深度有效值落在 **558–4164mm**,在理论区间内(略收缩,因极端视差处匹配本就稀疏)。(§4 给出越界实测印证。)

> 历史教训:早先 README 把 0.56–4.16m 当"规格量程"引用,其实是从数据有效值上下界反推的,循环论证。
> 本文用量程 = 视差窗 + fB/d 几何推导纠正之。**要改量程,只能改 `DISPARITY_OFFSET/NUM`(搜索窗)
> 或换更长基线/焦距的设备。**

### 3.3 深度精度 ΔZ = Z²/(f·B) —— 精度随距离平方退化的根源

对 Z=fB/d 微分,得**每 1 视差像素对应的深度增量**:

```
   ΔZ = Z² / (f·B)
```

代入 f·B=110080:

| 距离 Z | ΔZ(每视差像素) |
|---|---|
| 0.6 m | 3.3 mm |
| 1.0 m | 9.1 mm |
| 2.0 m | 36 mm |
| 3.0 m | 82 mm |

含义:深度被**视差量化**——视差每跳 1 像素,深度就跳 ΔZ。**ΔZ ∝ Z²**,所以越远深度越粗。
这是结构光(及一切双目)精度随距离平方退化的**几何根源**,不是器件缺陷。

### 3.4 子像素视差:为什么实际噪声远小于 1 视差步

§3.3 的 ΔZ 是"整数视差跳一格"的步长,看着很大(1m 处 9mm/格)。但 SGBM 做的是**子像素(sub-pixel)**
匹配——通过块相关度的亚像素插值,视差精度可到 0.1 像素量级。设子像素视差噪声为 σ_d(像素),则:

```
   深度噪声 RMS ≈ σ_d · Z² / (f·B)
```

实测反推(§5):在 1–3.3m 段,**σ_d ≈ 0.13 px,几乎恒定**(各点 0.114–0.138)。即无论距离远近,
单次匹配的视差抖动就是 ~0.13 像素;深度噪声 = 0.13 × ΔZ,于是完全继承 ΔZ ∝ Z² 的规律。
这是本设备精度曲线(§5)的理论解释,实测数据与之一致。

## 4. 工作量程:近端与远端极限

### 4.1 极限的计算方式与原理

如 §3.2:**近/远端极限 = 视差搜索窗的上下界经 Z=fB/d 换算**。

- **近端 Z_min = fB/d_max**:物体太近 → 视差 d 超过搜索窗上界 d_max → 左右图中物点位移过大,
  超出 SGBM 搜索范围 → 找不到匹配 → 深度无效。
- **远端 Z_max = fB/d_min**:物体太远 → 视差 d 小于搜索窗下界 d_min → 左右图几乎重合、视差太小,
  匹配歧变大 → 搜不到可靠匹配 → 深度无效。

为什么是有限窗而非 0~∞:**(a)** 视差越大搜索越慢、越易越界,**(b)** 视差太小则基线相对距离过短、
三角测量失效。设备出厂把窗设成 [25,187](对应 0.59–4.4m)是针对其典型用途的折中。

### 4.2 实测印证(越界 = 墙消失)

把相机对一面平墙,从 0.5m 逐步挪到 4.5m,记录深度有效率(`depth>0` 像素占比):

| 距离 | 有效率 | 现象 |
|---|---|---|
| **0.5m** | **6.7%** | 墙在 0.5m < 近端 0.59m → 整面墙深度无效,残存 6.7% 是墙后背景 |
| 0.6–3.7m | 75–91% | 量程内,墙完整可测 |
| **4.5m** | **36.2%** | 墙在 4.5m > 远端 4.4m → 墙无效,残存 36% 是近处地板/天花板/侧墙 |

两端越界时**墙本身消失**(深度无效),与 §3.2 推导的 0.59m/4.4m 边界吻合。
完整曲线见 §5 图(红 X 标出两个越界点)。

### 4.3 量程能不能改

- **软件**:改 `DISPARITY_OFFSET`(下界)/`DISPARITY_NUM`(窗宽)可移动/展宽量程,但代价是
  匹配速度与歧义;且这些参数是否开放写入视固件而定。
- **硬件**:量程 ∝ f·B,换更长焦距 f 或更长基线 B 的设备可整体外推量程。本设备固定。

### 5.1 实验方法:平面墙 + MAD 鲁棒平面拟合

对一面平墙、正对相机,在不同距离各采 3 帧(1280×960)。平整度 = 点云到拟合平面的残差。

**关键在"只算真墙上的点"**,否则远处视场溢出墙、地板/天花板混入会污染结果(曾因此把 2.5m 的 RMS
误算成 94mm)。方法:

1. 深度直方图找墙的尖峰(轴向深度众数)→ ±120mm 窗砍掉远处背景;
2. 窗内点 **MAD(中位绝对偏差)鲁棒迭代**拟合主平面 + 校验**正对**(`|法向·z轴|>0.9`);
3. 3×MAD 紧内点 = 真墙点 → 重拟合 → RMS/P95 只算这些。

MAD 比"标准差"抗污染:远处散乱背景不会抬高阈值。每距离 `flatness.txt` 记录完整指标。

### 5.3 印证 Z² 律:反推子像素 σ_d ≈ 0.13 px

按 §3.4,RMS = σ_d·Z²/(fB)。用实测 RMS 反推 σ_d(末列):**1–3.3m 段 σ_d = 0.114–0.138 px,
中位 0.126 px,几乎恒定**。即:

- 单次立体匹配的视差抖动稳定在 ~0.13 像素(子像素精度),与距离无关;
- 深度噪声完全继承 ΔZ ∝ Z² —— **几何决定,而非器件随距离变差**。

图中的灰色虚线即理论曲线 `0.126·Z²/(fB)`,与实测点吻合。这正是"深度精度随距离平方退化"的
直接验证:不是经验拟合,而是从 f、B、σ_d 三者推出的几何预测被数据印证。

### 5.4 远端平台与有效率断崖

- **近端 0.63m 的 σ_d=0.181 偏高**:极近距离处除视差量化外,传感器读噪声等贡献一个 ~0.4–0.5mm 的
  近端地板,RMS 略高于纯 Z² 预测。
- **远端 3.3–3.7m 的 σ_d 降到 0.099、RMS 平台(12.3→12.5mm 几乎不涨)**:接近远端极限时,
  **最差的匹配率先变无效(被剔)**,活下来的都是较好匹配 → RMS 不再涨,但**有效率断崖下滑**
  (90%→78%→75%)。即"过 3m 不再换精度,只丢覆盖"。

### 5.5 部署建议(距离选型)

| 距离 | 精度 (RMS) | 评价 |
|---|---|---|
| **0.6–1m** | 0.7–1.3 mm | 亚毫米~毫米级精密测量 |
| **1–2m** | 1.3–4.6 mm | **最佳折中区**,有效率 >90% |
| 2–3m | 4.6–12 mm | 厘米级,可用 |
| >3m | ~12 mm + 有效率塌 | 不建议 |

**选型原则**:按所需精度倒推安装距离(精度 ∝ Z²);要毫米级就装 1–2m;要亚毫米就靠近到 0.6m。
远距离大范围感知交给 LiDAR(见附录)。

## 6. 点云稀疏的来源与对策

稀疏(深度有效率不高)有五个来源,按可调性排序:

### (a) 场景与量程【影响最大】
相机平放桌面时,正下方/前景 <0.59m 的区域整块无效(视差超搜索窗,§4)。实测:平放(前景过近)→
有效率 6.8%;重新摆位让目标落在 0.6–4m 甜区 → 33%(640) / 更高(1280)。**单靠摆位可数倍提升。**

### (b) 降采样模式【纯赚,4× 点数】
默认 640×480 是从原生 1280×960 降采(`get_default_image_mode` 返回索引 0)。改 1280×960 后,
有效率几乎不变,**点数 ×4**,精度不降。**采集应默认用 1280×960**(`-dmode 1280`)。

### (c) SGBM 严苛度【密度/精度 trade-off】
默认重精度:`UNIQUE_FACTOR=80` + `LRC=on`(左右一致性,剔除遮挡/误匹配)+ 中值滤波。
放宽(`UNIQUE_FACTOR=80→20`、关 LRC,`-uniq 20 -nolrc`)→ 有效率 33%→47%,但引入更多误匹配、
丢失遮挡剔除,精度下降。要"精确"保留默认;要"更密"才放宽。

### (d) IR 增益【默认即最优,勿乱动】
- 出厂默认 gain=32。增益扫描(对**深度有效率**):`32→33.5%`, `64→25.8%`, `128→1.3%`, `200→0%`。
  **调高反而更差**(饱和/噪声破坏匹配纹理)。
- `-ir` 直存的 IR 帧全黑(max≈14)**不是增益/曝光不够**,是 depth+IR 同开时激光同步绑给 depth、
  IR 组件取到灭灯相位(§8.3)。gain 对这些直存帧无响应(无光可放大)。
- **设置(LASER_POWER/gain 等)会持久化存设备**,改过必须显式重置(gain→32、laser→power100/auto1)。

### (e) 结构光天性(无法消除)
玻璃、屏幕、黑色、强反光面打不回 IR 散斑 → 永远无效。办公室这类面多,会拉低有效率,属正常。

## 7. 采集配置建议

兼顾"尽可能多 + 尽可能精确":

1. **depth 用 1280×960**(满分辨率,纯赚 4×)。`-dmode 1280`。


## 8. 投射器(散斑)与 IR 直取 —— 排障记录

回答两个一度被误判的问题:**散斑投射器到底发不发射?** 和 **`-ir` 存的 IR 帧为什么全黑?**
结论均经对照实验证实,排除了"SDK 太新 / 接口代际不匹配 / 投射器坏了 / IR 相机坏了"等猜测。

### 8.1 设备代际 = Gige_2_0(旧 API 有效)

`DumpAllFeatures`:`TY_COMPONENT_LASER` 存在,`TY_INT_LASER_POWER`/`TY_BOOL_LASER_AUTO_CTRL`
均 access=3(可读写)。→ 本设备是 **Gige_2_0**,走旧 `TYSetInt/TYSetBool`(非 Gige_2_1 的
`LightControllerSelector`/`TYParamGetAccess`)。"SDK 太新致 LASER/gain no-op"的猜测**不成立**。

### 8.2 投射器确实发射,且是深度命脉

散斑投射器是立体匹配的人工纹理来源。对照实验(同摆位,640×480,各 3 帧平均):

| LASER 配置 | 深度有效率 |
|---|---|
| power=100, auto=1(出厂频闪) | **33.4%** |
| power=100, auto=0(手动常亮) | 33.2% |
| **power=0(关)** | **2.4%** |

关掉投射器,深度从 33% 暴跌到 2% —— **散斑是匹配纹理的来源,关掉几乎匹配不出深度。** 投射器正常。
`TYSetInt(TY_COMPONENT_LASER, TY_INT_LASER_POWER, …)` 读回 0↔100 正确、深度随之响应,旧 API 有效。

> ⚠️ `LASER_POWER` **持久化**。实验后必须 `-laser 100 -lauto 1` 恢复,否则下次裸采集(不传 `-laser`)
> 会用残留 power=0 → 深度归零。`main.cpp` 每次启动打印 `LASER now: power=X auto=Y` 供核查。

### 8.3 IR 帧全黑的真因:depth+IR co-enable 抢了激光同步

`-ir`(同时开 depth + 左右 IR)存出的 `ir_left/right_*.png` 长期 max≈14/255 近全黑,gain 0→255 无响应。
**不是故障,是光照路由**:投射器光照只路由给"主"流。depth 与 IR 同开时,激光频闪**绑给 depth 时序**,
深度引擎在亮的那一刻内部抓走 IR 图去匹配;旁路开的 `IR_CAM_LEFT/RIGHT` 在另一时刻取图 → 取到"灭灯相位"
→ 全黑、无光可放大。铁证:

| 模式 | 投射器 | IR 帧 mean / max / std |
|---|---|---|
| depth + IR 同开(`-ir`) | 开 | 7 / 14 / 5(黑) |
| depth + IR 同开(`-ir`) | 关 | 7 / 14 / 5(黑) |
| **IR-only(`-nodepth`)** | 开 | **199 / 255 / 78(亮)** |
| IR-only(`-nodepth`) | 关 | 19 / 50 / 2(黑) |

IR-only + 投射器开 → IR 帧全亮,Laplacian 纹理方差 646(vs 暗帧 105,6×),可见高密度随机点散斑。

![真散斑图(IR-only 模式拍的左右 IR 原始散斑)](assets/speckle_left_vis.png)

本设备**无独立 IR 泛光灯**(`TY_BOOL_IR_FLASHLIGHT` 在所有组件 `TYHasFeature=false`)。
要拍真散斑:`SimpleView_CaptureDump -ip .114 -n 2 -nodepth -color=off -laser 100 -ire 80`(§8.4)。

### 8.4 怎么拿真散斑图

```bash
# 正常采集(要 depth/color/点云):不要加 -ir,避免产出无用的暗 IR 帧
SimpleView_CaptureDump -ip 192.168.1.114 -n 6 -dmode 1280 -outdir <dir>
# 单独拍真散斑(IR-only, 牺牲当帧 depth):投射器同步给 IR 流 → IR 帧被照亮
SimpleView_CaptureDump -ip 192.168.1.114 -n 2 -nodepth -color=off -laser 100 -ire 80 -outdir <dir>
```

`main.cpp` 相关开关:`-laser <0..100>`(给值自动关 auto 进手动常亮)/ `-lauto <0|1>` /
`-irflash`(本设备无效)/ `-nodepth`(纯 IR)。每帧统计深度有效率(对比 LASER 开关的判据)。

## 9. RGB 镜头畸变(点云里直线弯曲的成因与修复)

带色点云里墙上**直线(凹槽)看着是弯的**,且弯曲和彩色图一模一样。

### 9.1 两个会误导的度量(先排雷)
- **点到平面平整度(§5 的 1.4mm)**:量的是离面 z 残差,看不出**平面内**的桶形畸变(桶形把直线在
  平面内掰弯,z 几乎不变)——平整度指标对它失明。
- **针孔拟合残差**:点云本就用 `X=(u-cx)·Z/fx` 生成,拿这公式反拟合当然残差 0,**循环论证**。
- **正确判据 = 直线特征**:用已知是直的凹槽看它直不直(镜头畸变经典检测法)。

### 9.2 诊断:弯的是颜色,不是几何
- **CloudCompare 决定性验证**:关掉点云 RGB 颜色、改按高度上色 → **凹槽立刻变直**。→ 几何没畸变,弯的是颜色。
- **几何为什么干净**:双目深度在 rectify(校正)后的图上算,IR 镜头畸变已消除;depth 存的是轴向 z
  (实测 `|depth − 点云.z| = 0.00 mm`),点云是干净针孔,直线不弯。
- **颜色为什么弯**:RGB 是**独立镜头**带桶形畸变;解码出的 BGR 带着它,贴到干净几何上,凹槽(靠颜色
  才看得见)就跟着 RGB 弯。图像和点云弯曲一模一样 = 同一份 RGB 镜头畸变。

### 9.3 RGB 畸变系数怎么来(读出厂标定,无需自标定)
```c
TY_CAMERA_CALIB_INFO color_calib;
TYGetStruct(hDevice, TY_COMPONENT_RGB_CAM, TY_STRUCT_CAM_CALIB_DATA, &color_calib, sizeof(color_calib));
```
`TY_CAMERA_CALIB_INFO` 含 `intrinsic.data[9]`(3×3:[fx,0,cx,0,fy,cy,0,0,1])与
`distortion.data[12]`(**Percipio 自定义 12 系数模型**,非 OpenCV 的 5/8 系数)。本机实测:
intrinsic fx=1864.8 fy=1865.3 cx=1278.9 cy=955.2;distortion 前 6 项
`-0.2334, 0.4031, -0.0002, 0.0004, 0.2073, 0.0268`(首项 k1=−0.2334 <0 → 桶形)。
`main.cpp` 启动时打印这组系数供核查。

### 9.4 去畸变怎么做(用 SDK 自带接口,别用 OpenCV)
用 `TYUndistortImage`(`TYImageProc.h`)——它懂 Percipio 12 系数模型;`cv::undistort` 模型不匹配,**不要用**。
```c
// 1) 解码 BGR 后, 用 color_calib 去畸变(NULL 新内参 = 保持原 fx/fy/cx/cy, 输出 pinhole 图)
TYUndistortImage(&color_calib, &srcImg, NULL, &dstImg, TY_LENS_PINHOLE);   // OK 后用 dst 替换
// 2) 贴点云时, color_calib 畸变清零(图已是 pinhole, 避免映射函数二次校正)
TY_CAMERA_CALIB_INFO calib_pin = color_calib;
memset(&calib_pin.distortion, 0, sizeof(calib_pin.distortion));
TYMapRGBImageToDepthCoordinate(&depth_calib, ..., &calib_pin, ..., mappedColor, ...);
```
要点:**只去 RGB**(depth/IR 已 rectify);去畸变后图是 pinhole,贴图 calib 必须清零畸变;
去畸变在**存 JPG 之前**做 → 存盘的 `color_*.jpg` 也一并去畸变了。

## 10. 标定参数能不能自己重新标定?

设备出厂标定存于各组件 `TY_STRUCT_CAM_CALIB_DATA`,`access=1` = **只读**,API 不能写回设备。
"重新标定"只能在**主机端读出 → 用自己的标定覆盖重算**,没法让 SDK 内置函数改用你的标定。

| 标定项 | 影响 | 能否自标 | 方法 |
|---|---|---|---|
| RGB 内参+畸变 | 彩色上色/对齐 | **能,易** | 棋盘格/Charuco + OpenCV `calibrateCamera`,主机端覆盖 `color_calib` |
| IR 内参+畸变 | 深度几何 | 能,麻烦 | 关投射器 + 外部 IR 补光(本设备无 IR 泛光灯,须自备)照棋盘格 |
| **双目外参(基线/整流)** | **深度量程精度(最关键)** | **实际不能** | 出厂锁死;SDK 设备端做 SGBM,塞不进去。覆盖 = 自拍左右 IR + 自整流 + 自立体匹配 = 重写深度引擎 |
| depth↔RGB 外参 | 彩色贴图对齐 | 能 | SDK 自带 `SimpleView_Registration` / `SimpleView_PixelsRegistration` |

**先验证"是不是真不准"**:目前证据都指向深度标定是准的——1m 平整度 1.4mm(§5)、量程吻合 fB/d(§3)、
`depth=轴向z`。唯一查出的毛病是 RGB 镜头畸变(§9),那是 RGB 相机的事,与深度标定无关。
→ 先量已知尺寸(误差应 <1%),对得上就别动深度标定。**真正该考虑重标的场景**:量已知尺寸明显偏
(深度量程问题,但双目外参标不了 → 返厂/Viewer 重标),或彩色整片对不齐(标 RGB),或相机摔过(标定漂移)。

## 附:与 LiDAR 的根本区别

LiDAR(禾赛/速腾/Livox)靠**飞行时间**(ToF,直接测光往返)得距离,每点独立、稀疏但远(百米级)。
本设备靠**双目立体匹配**(被动三角,投射器只补纹理),得**稠密深度图**(每像素一个深度),
但受基线限制量程短(米级)、受表面反射率影响大。二者互补:LiDAR 远而稀,结构光近而密。
本仓库的 7 路设备里,这台结构光负责**近场稠密 3D**,远距离大范围感知交给 LiDAR。
